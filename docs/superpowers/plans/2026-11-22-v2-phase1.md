## Item 1: Test hygiene (first)
- **`.env.test`.**
  - `config.py`: `env_file` comes from `os.environ.get("MNEMO_ENV_FILE", ".env")`.
  - `tests/conftest.py`: set `MNEMO_ENV_FILE=.env.test`, use `load_dotenv(".env.test")` instead of `.env`, and fail fast unless `MNEMO_DATABASE_URL` contains `test`.
  - Pop `ANTHROPIC_API_KEY` / `OPENROUTER_API_KEY` from `os.environ` unless running `-m eval`; eval runs read keys from the shell env.
  - Commit `.env.test.example`; `.env.test` goes in `.gitignore`.
- **LLM mocked by default.** The decomposer provider in tests is a `fake` scripted decomposer (fixture `fake_decomposer` returns given atoms/quotes), with `regex` available. Lifecycle tests already patch `lifecycle_service._get_client`; add an autouse guard that fails any unpatched Anthropic client construction outside `eval`.
- **Fake embedder.**
  - `embeddings.py` gets `embedding_backend: Literal["sentence_transformers","fake"]`.
  - The fake is a deterministic hashed bag of words (lowercased tokens plus bigrams → 768 dims, L2-normalised). Identical text gives identical vectors, and lexical overlap gives graded similarity, so most dedup, recall and edge tests stay meaningful.
  - Add `encode_batch(texts)` to both backends (needed for item 4).
  - Tests that genuinely need semantic similarity move under `eval`; the list goes in the report.
- **Broken tests.** Delete `tests/test_client.py`; the client lives in mnemo-client and has its own tests. Make `test_stats_includes_date_range` deterministic; its flakiness came from the live LLM, so fake decomposer plus fixed dates.
- **Local test DB.** A docker container `mnemo-test-pg` from `pgvector/pgvector:pg16` (0.8.x) on port 5433 with database `mnemo_test` and roles `mnemo` + `mnemo_migrator` mirroring production grants. Built from `schema.sql` + `mnemo migrate`. It holds no production data.
- **CI.** `.github/workflows/tests.yml` runs:
  - a pgvector service
  - `uv sync --frozen`
  - `psql -f schema.sql`
  - `mnemo migrate --database-url …`
  - `pytest` (non-eval) with `MNEMO_EMBEDDING_BACKEND=fake`, `MNEMO_DECOMPOSER_PROVIDER=fake`, and no secrets
- **Exit for item 1.** The full suite is green offline: verify by running with network disabled (`unshare -n` or an unset-key run) and by CI on push.

## Item 2: Design note `docs/phase1-design.md` → **STOP, G1**
It covers items 3–7 in full: migration 010 DDL, request/response models, the full text of prompt v2, the deterministic checks, and the MCP tool signatures. Decisions I'll propose in it:

- **Migration `010_sources.sql`.**
  - New `sources` table per spec, with a CHECK on `origin_class` and default `unspecified`.
  - Index on `sources(store_id)`.
  - `atoms` gains `source_id` (FK, `ON DELETE SET NULL`), `source_quote` and `verification JSONB`.
  - `GRANT SELECT, INSERT, UPDATE, DELETE ON sources TO mnemo`. Phase 0 showed the app role needs explicit grants, since `mnemo_migrator` owns the tables.
  - `schema_migrations` row. `tests/conftest.py _CLEAN` adds `sources`.
- **Provider guard (rule 4).**
  - The `openrouter` decomposer refuses to run unless `MNEMO_ALLOW_NON_ANTHROPIC_DECOMPOSER=true`.
  - The production container never sets that flag.
  - The bake-off script connects only to `mnemo_eval`, or to synthetic data.
- **`store_failures`.** Stop copying `original_text` into it; the `sources` row now holds the text. Error and trace only.
- **Sync remember and old clients.** The response is a superset of today's (still 201, still has `store_id`), so 0.5.0 clients keep working. To stay well under the 30 s client timeout, chunks over 8,000 characters are decomposed concurrently (bounded `asyncio.gather`). Latency numbers come at G2.
- **Flag downgrade.** A flagged atom moves one band down the `_confidence_to_beta` ladder (`llm_decomposer.py`).

## Items 3–8: Implementation (after G1)
Each item gets small commits with tests.

### Item 3: Sources
- Add `speaker`, `addressee`, `channel` and `origin_class` to `RememberRequest` (`models.py`). `speaker` defaults to the agent's name.
- The route writes `store_jobs` and `sources` in its own transaction before decomposition.

### Item 4: Store path
Rewrite `store_background` / `store_from_text` (`services/atom_service.py:495–702`) into:
1. `prepare` — decompose plus `encode_batch`, with no connection held.
2. `persist(conn, …)` — one transaction: dedup check (unchanged logic, `_check_duplicate`/`_merge_duplicate`), `_insert_atom` with `source_id`/`source_quote`/`verification`, `_create_similarity_edges`, `_create_cross_call_edges`, and the `decomposer_usage` row.
3. Background lifecycle — tasks kept in a module-level set, and `detect_lifecycle_relationships` refactored so no connection is held during its LLM call (`lifecycle_service.py`).

Routes (`routes/memory.py`):
- `wait=true` returns the full atom list; `wait=false` keeps today's queued path.
- Failure → 502 `status: failed`.
- `POST /stores/{id}/retry` re-reads `sources.text`.
- `GET /stores/{id}/status` returns atoms (join on `atoms.source_id`).
- `main.py` lifespan marks `store_jobs` stuck >10 min as failed.
- `sync_store_for_tests` becomes unnecessary for sync and remains only for `wait=false` tests.

### Item 5: Decomposer v2
- New package `mnemo/server/decomposers/`: a `Decomposer` protocol with `anthropic`, `openrouter`, `regex` and `fake` implementations, selected by `MNEMO_DECOMPOSER_PROVIDER` / `MNEMO_DECOMPOSER_MODEL`.
- `decomposer_version = provider:model:prompt_v2`.
- Anthropic implementation:
  - Tool use with a JSON schema for structured output.
  - `max_retries=2`, explicit for timeout/429/5xx.
  - `stop_reason == "max_tokens"` is a failure.
  - Malformed items are skipped with a warning.
  - No `cache_control`.
  - No regex fallback.
- Paragraph splitter at about 8,000 characters.
- Prompt v2 is written in the design note.
- `mnemo/server/services/grounding.py` implements the three checks (`ungrounded_quote`, `abbreviation_altered`, `no_subject`), unit-tested on synthetic strings.
- Old `llm_decomposer.py` is reduced to helpers that are still used (`_confidence_to_beta`, `_parse_remembered_on`, the state-claim backstop) or removed.

### Item 6: Read side
- `RetrieveRequest` gets `since`, `until` and `atom_types`, filtered on `COALESCE(remembered_on, created_at)` in `atom_service.retrieve`.
- `POST /agents/{id}/recent` (no embedding, no access update).
- `GET /agents/me`, registered before `/agents/{agent_id}` in `routes/agents.py`, built from `AuthContext.agent_id`.
- `source_id` / `origin_class` added to `_row_to_atom_response` and to the recall SQL.

- Default `verbosity="full"` with a per-atom character cap.
- New tools `mnemo_recent`, `mnemo_forget` and `mnemo_store_status`.
